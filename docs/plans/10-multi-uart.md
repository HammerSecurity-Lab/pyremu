# 计划十 多串口支持

**状态**: 待确认

## Context

芯片设备树可以声明多个串口节点, 例如 Arm FVP 的设备树有四个 `arm,pl011`,
树中的每个串口都有自己的区间与中断源. pyremu 目前只建模一个串口:

- `PeripheralConfig` 只有单个 `uart_base` 与 `uart_irq`;
- `ChipPeriph.uart` / `ChipIrq.uart` 只取树中第一个串口节点;
- `SetupOps._setup_peripherals` 只创建一个 `self.uart` 并注册;
- `generic_ops` 的 `RunConfig.uart` 与 Rust 侧 `FfiUartCtx` 各只有一个串口上下文,
  加速执行引擎只为该串口保留内联读写路径, 其余串口地址按设备区间退出到 Python;
- 设备树生成只为第一个串口写 `serial@` 节点与 `serial0` 别名;
- 终端桥接 (termio) 与 hart 日志都绑定到 `self.uart`.

`periph_from_chip` 目前把树中除第一个串口以外的串口节点列为「未提供模型」.

## 已确认的行为

1. 芯片设备树中声明的串口全部注册为模拟串口, 各自持有独立区间与中断源.
2. 串口在配置中以列表组织, 每个串口有自己的名称或编号, 首个串口保留单串口
   语义的名称.
3. 每个串口有自己的终端服务线程, 宿主标准输入输出绑定其中一路, 由其指定.
4. 设备树为每个串口生成节点与 `serialN` 别名.
5. 既有单串口用法 (读取 `emu.uart`、终端桥接、hart 日志) 保持可用.

## 待确认

- 宿主控制台绑定哪一路串口: 取第一个、由 `--console=serialN` 指定, 还是取树中
  `/chosen/stdout-path` 指向的节点.
- 非控制台串口是否需要终端服务线程; 若不需要, 其读写只经 MMIO 与调试器查看.
- 串口列表的表示: `PeripheralConfig.uarts: tuple[UartConfig, ...]` 取代现有的
  `uart_base`/`uart_irq`, 还是保留首个串口字段并新增 `extra_uarts`. 前者命名
  对称, 但要改所有调用方与平台文件; 后者兼容, 但留下一个笼统名与列表并存.
- 加速执行引擎是否把全部串口纳入内联路径 (串口表上下文), 还是只保留第一个
  串口的内联路径, 其余经 MMIO 退出.

## 步骤

### 一. 配置与解析

- 在平台配置中引入串口条目 (区间、中断源、名称), 以列表保存.
- `ChipDt` 收集全部串口节点的区间与中断源, 首个串口保留现有单值字段.
- `_unsupported_devices` 的认领集合纳入全部串口区间.
- 已有 JSON/TOML/YAML 反序列化兼容单串口写法.

### 二. 装配与设备表

- `SetupOps` 按列表创建并注册每个 `UART`, 保留 `self.uart` 指向第一个串口.
- 设备表与 `devices` 命令按区间列出全部串口.
- 块设备补充、中断控制器补充等选区间逻辑避开全部串口区间.

### 三. 终端服务线程

- 每个启用终端服务的串口各自持有接收环形缓冲、发送缓冲与服务线程.
- 宿主标准输入输出绑定到指定的那一路; 其余串口只提供 MMIO 与调试器访问.
- hart 日志写入与终端回显的路由按绑定串口确定.

### 四. 设备树

- 为每个串口生成 `serial@` 节点, 共用固定的时钟节点.
- 生成 `serial0`、`serial1` 等别名; `/chosen/stdout-path` 指向绑定的串口.

### 五. 加速执行引擎

- 方案一: `RunConfig` 传入串口上下文列表, Rust 侧改为串口表 (指针与数量),
  批次内全部串口走内联读写.
- 方案二: 仅第一个串口内联, 其余串口地址留在设备区间内, 由 MMIO 退出到
  Python 处理. 先按方案二实现, 高频率访问确有需要时再扩展为串口表.

### 六. 用例

- 芯片设备树含两个串口: 配置列出两路, 两个区间都注册, 设备表列出两路.
- 向第二个串口写入后经调试器读回, 且不经过第一个串口的发送缓冲.
- 首串口缺失时列表与 `emu.uart` 的取值.
- 加速执行: 第二个串口的 MMIO 访问退出到 Python 后结果正确.

## 验收

- 单串口平台行为与用例保持不变.
- 多串口平台的每个串口可独立读写, 中断源互不相同.
- 终端桥接只绑定指定的那一路, 其余串口不读取宿主输入.
