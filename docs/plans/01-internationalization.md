# 计划一 代码内使用者可见字符串的国际化 (搁置)

**状态**: 搁置

## Context

宿主侧的使用者可见文本目前全部以中文字面量写在 Python 源码中: 调试器输出与帮助、命令行参数说明、平台配置解析的错误、外设与中断的告警、异常与提示文本。切换语言必须修改源码。

## 状态

搁置。先完成计划四, 之后重新讨论选型与实施顺序。原方案的 gettext 实现已作废。

## 已确认的约束

- 不采用 GNU gettext 的 `.po` / `.mo` 格式, 译文改由结构化消息文件承载。
- 范围只包括代码内的使用者可见字符串; `docs/` 与 `CLAUDE.md` 不做多语言版本。
- 客机侧输出 (固件、内核、`sbi_printf` 与驱动日志) 必须保持 ASCII, 不纳入。
- 注释、文档字符串、标识符、GPR/CSR 名称、段名、反汇编助记符与符号名不纳入。
- 迁移只改变取文本的方式, 不改变默认语言下既有输出的文本、顺序与格式。

## 待定

- 选型: 从以结构化消息文件承载译文的方案中选取, 例如 Fluent 的 `.ftl`; 需先确认从 Python 源码提取消息的工具支持, 以及约 1800 处调用点的改造成本。
- 迁移顺序、测试与验收标准在选型确定后重写。
