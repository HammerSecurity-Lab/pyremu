# 计划二 `pyremu/_native` 内与项目规范相悖的注释重写

**状态**: 待确认

## Context

`pyremu/_native/` 的 Rust 源码 (`cpu/` 与 `termio/`) 的注释与文档注释沿用英文,
部分表述与 CLAUDE.md 的"注释与用语规范"不一致: 使用比喻或口语化表述、以 `->`
表示"变为"、在中文句中混排英文、用括号补充说明已讲完的内容、布尔量不带 `is_` /
`has_` 前缀。这些注释在跨 FFI 边界排查 (结构体布局、退出原因、PLIC 同步) 时是主要
依据, 表述不统一会降低其可核查性。

## 范围

- `pyremu/_native/cpu/src/*.rs` 与 `pyremu/_native/termio/src/*.rs` 内的注释、
  文档注释与行内注释。
- 不改变任何标识符、常量名与代码行为; 不触碰 `#[repr(C)]` 结构体的字段与顺序。

## 依据

按 CLAUDE.md 的"注释与用语规范"逐条核对, 重点:

- 注释用中文书写; 标识符、接口名与代码引用保留英文原文, 不在同一句中中英混排。
- 动作使用标准动词 (创建/进入/恢复/终止/读取/写入/删除/移除), 不使用比喻、拟人
  与口语化表述。
- 不把 `->` 当作"变为"使用, 写作"变为"或直接引用原文。
- 布尔变量与布尔参数以 `is_` 或 `has_` 前缀声明。
- 括号只用于枚举返回值、参数这类独立信息, 不用于补充说明已讲完的内容。
- 同一概念在全项目只用同一个词, 术语表登记的词照写。
- 注释只写该处代码当前的行为与约束, 不写改动理由与命名取舍。
- 改动一处注释时, 同一函数的整段注释一并检查, 与代码不符的陈述一并更新。

## 步骤

1. 逐文件通读, 登记与规范相悖的原句与改写后的句子, 形成对照清单。
2. 按清单逐条改写; 英文文档注释改写为中文, 保留其中作为代码引用的标识符。
3. 每改完一个文件, 核对该文件内被改动函数的行为描述与当前代码是否一致。
4. 校验: `cargo fmt --check` 与 `cargo build --release` 保持不变, 不引入代码改动;
   运行 `cargo test --manifest-path pyremu/_native/Cargo.toml` 确认既有用例结果不变。

## 说明

- 本计划只改注释, 不改任何可执行语义; 与已完成的 emulator.py 拆分互不影响。
- 已有的英文日志文本与 `#[allow(dead_code)]` 等属性不属于注释范围, 不在本计划内。
