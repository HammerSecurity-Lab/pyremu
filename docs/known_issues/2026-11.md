# 2026-11 已知缺陷

## 2026-11-16 — 客机终端输入长行时整行被清空

**现象** (2026-11-16): 在客机 shell 中输入较长的命令行, 越过约第 80 列时整行显示
被清空. 例如输入 `sed -n "107p" ... | python3`, 光标到达 `hon3` 处时该行被清除;
命令本身仍可执行.

**已确认**:
- UART 的发送路径逐字节直通 (`UART._write_reg` 每个字节立即交给回调或 `os.write`),
  模拟器侧没有行缓冲, 也没有终端宽高协商: 仓库内没有 `winsize`、`TIOCGWINSZ`
  或 `cols` 的处理, 内核命令行只有 `console=ttySIF0`.
- 串口 tty 使用内核默认窗口 80×24. 命令行越过该列数时, 客机 shell 的行编辑按窄
  终端计算换行与重绘序列; 宿主终端更宽时这些光标移动落在错误的列上, 表现为整行
  被清除.

**未修复**. 两条候选方向:
- 客机 rootfs 的启动脚本对控制台执行 `stty cols/rows`, 取一个足够宽的固定值;
- 由模拟器把宿主终端尺寸写入设备树的 `/chosen`, 客机初始化脚本读出后设置.
  串口本身不承载窗口尺寸, 必须由客机配合, 单侧无法完成.
